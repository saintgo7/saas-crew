## 1. 전제 및 목표
본 문서는 `saas-crew` 프로젝트의 복잡한 항공사 승무원 관리 도메인을 효율적으로 개발하기 위한 LLM 에이전트 오케스트레이션 전략을 정의한다. 항공 스케줄링은 법적 규제(비행시간 제한), 자격 요건(기종/직급), 정산 로직이 복잡하게 얽혀 있어 단일 컨텍스트로 처리 시 환각(Hallucination) 발생 가능성이 높다.

**핵심 목표:**
- **도메인 격리**: 10개의 독립적인 슬라이스로 나누어 각 에이전트가 담당하는 컨텍스트 윈도우를 최적화한다.
- **North Star 달성**: '월간 활성 승무원당 스케줄 확정 소요 시간'을 단축하기 위해 스케줄 생성-검증-확정 프로세스의 병렬 처리를 구현한다.
- **정밀도 확보**: PostgreSQL의 Range Types와 Drizzle ORM의 타입 안정성을 보장하는 코드 생성 체계를 구축한다.

## 4. Handoff 규칙
에이전트 간 작업 전환 시 데이터 누락을 방지하기 위해 다음의 표준 Handoff 포맷을 준수한다.

**Handoff 프로세스:**
1. **Context Export**: 송신 에이전트는 현재까지 완료된 작업, 사용된 변수명, 참조한 DB 스키마를 요약한다.
2. **Dependency Mapping**: 수신 에이전트가 작업하기 위해 필요한 선행 조건(예: SL-04 완료 후 SL-06 진행)을 명시한다.
3. **Interface Agreement**: API 엔드포인트, DTO 구조, Zustand 상태 구조를 정의하여 전달한다.

**전달 양식:**
- `From`: [슬라이스 ID] $\rightarrow$ `To`: [슬라이스 ID]
- `Status`: [Completed / In-Progress / Blocked]
- `Key Artifacts`: [관련 파일 경로 및 함수명]
- `Next Action`: [수신 에이전트가 즉시 수행해야 할 작업]

## 5. 에스컬레이션
작업 수행 중 발생하는 병목 현상 및 기술적 충돌 해결 절차를 정의한다.

**에스컬레이션 트리거:**
- **논리 충돌**: SL-04(스케줄)와 SL-06(규정) 간의 검증 로직이 상충하여 무한 루프가 발생할 때.
- **성능 저하**: PostgreSQL 쿼리 실행 시간이 500ms를 초과하여 인덱스 재설계가 필요할 때.
- **보안 취약점**: RBAC 권한 우회 가능성이 발견되어 권한 매트릭스 수정이 필요할 때.

**처리 단계:**
1. **Level 1 (Sonnet $\rightarrow$ Sonnet)**: 동일 계층 에이전트 간의 인터페이스 조정 시도.
2. **Level 2 (Sonnet $\rightarrow$ Opus)**: 아키텍처 설계 변경이 필요하거나 도메인 간 우선순위 결정이 필요할 때 Opus에게 판단 요청.
3. **Level 3 (Opus $\rightarrow$ Human)**: 비즈니스 요구사항의 모호함으로 인해 결정이 불가능한 경우, 프로젝트 매니저에게 최종 의사결정 요청.
