# 보고서 시스템 (PDF 템플릿) 설계서

## 1. 문서 정보

### 1.1 개요
본 문서는 `saas-crew` 프로젝트의 핵심 출력물인 비행 스케줄 및 정산 명세서의 PDF 생성 시스템 설계를 정의한다. Puppeteer를 활용하여 HTML/CSS 기반의 템플릿을 PDF로 렌더링하며, 항공 산업의 특성상 요구되는 정밀한 데이터 그리드와 법적 증빙을 위한 서명 체계를 포함한다.

### 1.2 변경 이력
| 버전 | 날짜 | 작성자 | 변경 내용 | 비고 |
| :--- | :--- | :--- | :--- | :--- |
| v1.0 | 2024-05-22 | 시스템 설계자 | PDF 템플릿 T01~T15 정의 및 렌더링 파이프라인 설계 | 초안 |

### 1.3 관련 문서
- `app-sap-saas` 표준 아키텍처 가이드
- RBAC 권한 정의서 (G, CA, SC, QM, PA, SA)

## 3. 한글 폰트 처리

Puppeteer는 Headless Chrome 기반으로 동작하므로, 서버 환경(Docker) 내에 한글 폰트가 설치되어 있지 않을 경우 글꼴 깨짐(Tofu 현상)이 발생한다. 이를 방지하기 위해 다음과 같은 전략을 적용한다.

1. **폰트 선정**: 가독성과 라이선스 문제를 고려하여 `Pretendard` 또는 `Noto Sans KR`을 표준 폰트로 지정한다.
2. **설치 경로**: Dockerfile 빌드 단계에서 `/usr/share/fonts/truetype/` 경로에 폰트 파일을 복사하고 `fc-cache -fv` 명령어를 통해 폰트 캐시를 갱신한다.
3. **CSS 적용**: 템플릿 CSS의 `@font-face`를 통해 폰트를 명시적으로 지정하며, `font-family: 'Pretendard', sans-serif;`를 기본값으로 설정하여 렌더링 일관성을 유지한다.
4. **렌더링 최적화**: 폰트 파일의 크기로 인한 PDF 생성 속도 저하를 막기 위해 WOFF2 포맷을 우선적으로 사용한다.

## 4. 서명 이미지

법적 효력이 필요한 T02(정산서), T04(평가서), T07(승인서) 등의 문서에는 전자 서명 이미지가 삽입되어야 한다.

1. **저장 방식**: 서명 이미지는 `Cloudflare R2`에 PNG(투명 배경) 형태로 저장되며, DB에는 해당 파일의 URL 경로를 저장한다.
2. **삽입 프로세스**: 
   - Puppeteer가 HTML을 렌더링할 때, `<img>` 태그의 `src`에 R2 URL을 바인딩한다.
   - `waituntil: 'networkidle0'` 옵션을 사용하여 모든 서명 이미지가 완전히 로드된 후 PDF로 변환한다.
3. **보안 처리**: 서명 이미지는 민감 정보이므로, R2의 Pre-signed URL을 생성하여 유효 시간이 짧은 임시 링크를 통해 렌더링 프로세스에 전달한다.
4. **위치 지정**: CSS Absolute Positioning을 사용하여 템플릿 하단 서명란의 정해진 좌표에 정확히 배치한다.

## 5. 페이지 분리

비행 스케줄(T01)이나 정산 상세 내역(T13)과 같이 데이터 양이 가변적인 문서의 경우, 페이지 분리 제어가 필수적이다.

1. **강제 페이지 분리**: CSS의 `break-before: page` 또는 `break-after: page` 속성을 사용하여 섹션별로 페이지를 강제 분리한다.
2. **헤더/푸터 반복**: `page.pdf()` 옵션의 `displayHeaderFooter: true`를 활성화하고, `headerTemplate`과 `footerTemplate`을 통해 페이지 번호와 문서명을 모든 페이지에 삽입한다.
3. **콘텐츠 절단 방지**: 표(Table)의 행(`tr`) 중간에서 페이지가 끊기는 것을 방지하기 위해 `break-inside: avoid` 속성을 적용하여 데이터 무결성을 시각적으로 보장한다.
4. **여백 설정**: `margin` 옵션을 통해 상하좌우 15mm의 여백을 설정하여 인쇄 시 내용이 잘리지 않도록 설계한다.

## 6. Word 변환

사용자의 수정 요청이나 외부 제출을 위해 PDF 외에 Word(.docx) 형식의 변환 기능을 제공한다.

1. **변환 전략**: Puppeteer로 생성된 PDF를 직접 변환하는 대신, 템플릿으로 사용된 HTML 구조를 기반으로 `html-docx-js` 또는 서버 사이드 변환 라이브러리를 활용한다.
2. **레이아웃 대응**: PDF의 고정 레이아웃(Fixed Layout)과 달리 Word는 유동 레이아웃(Fluid Layout)이므로, 표(Table) 중심의 단순화된 HTML 구조를 별도로 정의하여 변환 시 레이아웃 붕괴를 최소화한다.
3. **폰트 매핑**: PDF에서 사용한 `Pretendard` 폰트를 Word 표준 폰트(맑은 고딕 등)로 매핑하여, 파일을 수신한 사용자의 환경에서도 폰트 깨짐 없이 출력되도록 처리한다.
4. **제한 사항**: 복잡한 CSS Grid나 Absolute Positioning이 적용된 서명 위치는 Word 변환 시 정밀도가 떨어질 수 있으며, 이는 '참조용 문서'임을 명시하여 안내한다.
