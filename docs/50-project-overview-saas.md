## 1. 프로젝트 기본 정보
본 프로젝트는 항공사 객실 승무원의 복잡한 비행 스케줄링, 법적/사내 자격 관리, 그리고 비행 수당 정산을 통합 관리하는 B2B SaaS 솔루션이다. 기존의 수동 엑셀 관리 및 파편화된 시스템을 통합하여 운항 관리 효율성을 제고하고 승무원의 스케줄 접근성을 높이는 것을 목적으로 한다.

- **프로젝트 명**: saas-crew
- **핵심 목표**: 스케줄 확정 프로세스의 자동화 및 정산 무결성 확보
- **North Star Metric**: 월간 활성 승무원당 스케줄 확정 소요 시간 (Time-to-Finalize Schedule per Crew)
- **주요 페르소나**: 
    - 이정훈 (운항관리팀 스케줄링 매니저): 스케줄 편성, 자격 검증, 정산 승인 담당
    - 박소희 (객실 승무원): 개인 스케줄 확인, 자격 갱신 신청, 정산 명세서 확인 담당

## 2. 사업 범위 (MVP/Phase 2)
서비스의 안정적인 시장 진입을 위해 핵심 기능 중심의 MVP를 우선 구축하고, 고도화 기능은 Phase 2로 분리하여 개발한다.

| 구분 | MVP (최소 기능 제품) | Phase 2 (고도화) |
| :--- | :--- | :--- |
| **스케줄 관리** | 월간 스케줄 편성, 개인별 캘린더 뷰, 스케줄 확정/공지 | AI 기반 최적 경로 배정, 자동 스왑(Swap) 요청 시스템 |
| **자격 관리** | 자격증(안전/서비스) 유효기간 관리, 만료 알림 | 온라인 교육 연동, 자격 인증 자동 검증 시스템 |
| **정산 시스템** | 비행 시간 기반 기본 수당 계산, PDF 명세서 생성 | 복합 수당(체류비, 특수노선) 자동 계산, 세무 신고 연동 |
| **결제/구독** | 항공사 단위 구독 결제 (토스페이먼츠) | 사용자 수 기반 슬라이딩 스케일 요금제 적용 |
| **인프라** | Docker 기반 셀프 호스팅, 기본 RBAC 적용 | 멀티 테넌시 아키텍처 최적화, 글로벌 리전 확장 |

## 3. 사용자 역할 체계 (RBAC)
시스템 권한은 직무와 책임 범위에 따라 6가지 역할로 세분화하여 데이터 접근 제어 및 작업 권한을 관리한다.

| 역할 코드 | 역할 명칭 | 주요 권한 및 책임 | 접근 범위 |
| :--- | :--- | :--- | :--- |
| **G** | General Admin | 시스템 전체 설정, 테넌트 관리, 결제 관리 | 전 시스템 |
| **QM** | Queue Manager | 전체 스케줄 편성, 자격 검증 승인, 정산 최종 확정 | 전 승무원 데이터 |
| **PA** | Planning Admin | 노선별 스케줄 초안 작성, 인력 배치 최적화 | 배정 노선 데이터 |
| **SA** | Settlement Admin | 비행 기록 검토, 수당 계산 검증, 명세서 발행 | 정산 관련 데이터 |
| **CA** | Cabin Chief | 팀원 스케줄 조정 요청 승인, 팀 내 자격 현황 모니터링 | 소속 팀 데이터 |
| **SC** | Crew | 본인 스케줄 조회, 자격 갱신 신청, 정산 내역 확인 | 본인 데이터 |

---

## 4. 핵심 비즈니스 프로세스
본 서비스의 핵심 워크플로우는 [스케줄 편성 $\rightarrow$ 자격 검증 $\rightarrow$ 비행 수행 $\rightarrow$ 정산]의 순환 구조를 가진다.

1. **스케줄 편성 및 확정**: `PA`가 노선별 필요 인원을 산출하여 초안을 작성하면, `QM`이 승무원의 휴무일과 법적 비행 제한 시간을 검토하여 최종 확정한다. 확정 시 `SC`에게 실시간 알림이 전송된다.
2. **자격 검증 프로세스**: 스케줄 배정 전, 해당 노선에 필요한 자격(예: 특정 기종 자격, 언어 자격) 보유 여부를 시스템이 자동 체크한다. 만료 예정 자격 보유자는 `SC`와 `QM`에게 사전 경고가 발송된다.
3. **비행 기록 및 정산**: 실제 비행 완료 후 비행 시간이 기록되면, `SA`가 설정된 수당 규칙에 따라 정산금을 계산한다. `Puppeteer`를 통해 생성된 PDF 명세서가 `SC`에게 제공되며, `토스페이먼츠` API를 통해 정산금이 지급된다.

## 5. 기술 아키텍처
데이터 무결성과 실시간성, 그리고 빠른 개발 속도를 위해 Next.js 풀스택 프레임워크와 관계형 데이터베이스 중심의 스택을 채택한다.

- **Frontend**: `Next.js 14 (App Router)`를 사용하여 관리자 대시보드의 SSR/ISR 최적화를 구현하며, `shadcn/ui`와 `Tailwind CSS`로 정밀한 데이터 그리드를 구축한다. 상태 관리는 `Zustand`와 `TanStack Query`를 조합하여 서버 데이터 캐싱 효율을 극대화한다.
- **Backend**: `Next.js Route Handlers`를 통해 API 서버를 단일화하고, `Drizzle ORM`을 사용하여 PostgreSQL의 타입 안정성을 확보한다. 복잡한 정산 및 PDF 생성 작업은 `BullMQ`와 `Redis` 기반의 비동기 큐로 처리하여 메인 스레드의 부하를 방지한다.
- **Database**: `PostgreSQL 16`의 `Range Types`를 활용하여 비행 시간대의 중복 여부를 DB 레벨에서 검증하며, `PgBouncer`를 통해 동시 접속자 수 증가에 따른 커넥션 풀을 관리한다.
- **Infrastructure**: `Docker` 기반의 셀프 호스팅 환경을 구축하고 `Cloudflare Tunnel`을 통해 외부 노출을 제어한다. 예상 월 비용은 개발 환경 $0~10, 운영 환경 $50~150 수준으로 산정한다.

## 6. 지원 표준
시스템의 확장성과 유지보수성을 위해 다음의 표준을 준수한다.

- **인증 표준**: `NextAuth.js v5`를 기반으로 한 Credentials 인증 및 RBAC(Role-Based Access Control) 표준 적용.
- **데이터 표준**: ISO 8601 표준 시간 포맷 사용 및 UTC 기준 저장 후 클라이언트 타임존 변환 처리.
- **API 표준**: RESTful API 설계 원칙 준수 및 JSON 기반 데이터 교환.
- **배포 표준**: Docker 컨테이너 이미지 기반의 불변 인프라(Immutable Infrastructure) 전략 채택.

## 7. 프로젝트 리스크
개발 및 운영 단계에서 예상되는 주요 리스크와 대응 방안은 다음과 같다.

- **데이터 무결성 리스크**: 스케줄 중복 배정 또는 정산 금액 오계산 발생 가능성. $\rightarrow$ PostgreSQL의 `EXCLUDE` 제약 조건 및 트랜잭션 격리 수준(Serializable) 설정을 통해 원천 차단.
- **성능 저하 리스크**: 대규모 승무원의 동시 스케줄 조회 시 렌더링 지연. $\rightarrow$ TanStack Query의 캐싱 전략 및 PostgreSQL 인덱스 최적화, PgBouncer 도입으로 해결.
- **법적 규제 리스크**: 항공법 및 노동법에 따른 비행 시간 제한 규정 변경. $\rightarrow$ 비즈니스 로직을 하드코딩하지 않고, 관리자 페이지에서 설정 가능한 '정책 엔진' 형태로 구현하여 유연하게 대응.

## 8. 용어 정의
| 용어 | 영문명 | 정의 |
| :--- | :--- | :--- |
| **스케줄 확정** | Schedule Finalization | 편성된 비행 일정에 대해 관리자가 최종 승인하여 승무원에게 공지하는 상태 |
| **자격 관리** | Qualification Mgmt | 안전 교육, 기종 교육 등 승무원이 비행을 수행하기 위해 갖춰야 할 법적/사내 자격 유지 관리 |
| **정산 명세서** | Settlement Statement | 비행 시간, 수당, 공제액 등이 상세히 기록된 월별 지급 내역서 |
| **테넌트** | Tenant | SaaS 서비스의 개별 고객사인 항공사 단위의 독립된 데이터 격리 공간 |
| **비행 제한 시간** | Flight Time Limitation | 항공법에 의거하여 승무원이 일정 기간 내 수행할 수 있는 최대 비행 시간 |
