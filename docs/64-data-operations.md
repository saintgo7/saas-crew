## 3. 시드 스크립트

Drizzle ORM을 사용하여 데이터베이스 초기 상태를 구축한다. 시드 스크립트는 개발 환경(Dev)과 테스트 환경(Test)으로 구분하여 실행하며, PostgreSQL 16의 Range Types를 활용해 스케줄 중복을 방지하는 제약 조건을 포함한다.

### 3.1 시드 데이터 구성
- **User Seed**: RBAC 역할별(G, CA, SC, QM, PA, SA) 계정 생성 및 NextAuth.js 연동 데이터.
- **Qualification Seed**: 항공사 표준 기종 자격(B737, A321 등) 및 필수 안전 교육 커리큘럼.
- **Schedule Seed**: 3개월 분량의 가상 비행 스케줄 (정상, 변경, 취소 케이스 포함).
- **Payroll Seed**: 토스페이먼츠 연동 테스트를 위한 가상 정산 기초 데이터.

### 3.2 실행 프로세스
1. `npm run db:push`: 스키마 최신화
2. `npm run db:seed`: `seed.ts` 실행을 통한 기초 데이터 삽입
3. `npm run db:verify`: 데이터 무결성 및 관계 설정 검증

## 4. testcontainers

통합 테스트의 신뢰성을 위해 실제 PostgreSQL 16 환경을 컨테이너로 띄워 테스트를 수행한다. 이는 H2와 같은 인메모리 DB에서 발생할 수 있는 PostgreSQL 전용 기능(Range Types, JSONB)의 동작 차이를 제거하기 위함이다.

### 4.1 구성 전략
- **이미지**: `postgres:16-alpine` 사용.
- **라이프사이클**: 테스트 스위트 시작 시 컨테이너 기동 $\rightarrow$ Drizzle 마이그레이션 적용 $\rightarrow$ 테스트 수행 $\rightarrow$ 컨테이너 폐기.
- **연동**: `PgBouncer` 설정을 모사하여 커넥션 풀링 환경에서의 트랜잭션 격리 수준을 검증한다.

### 4.2 검증 대상
- **스케줄 중복 체크**: 동일 승무원에게 겹치는 시간대의 비행 스케줄이 할당될 때 발생하는 DB 제약 조건 위반 여부.
- **정산 트랜잭션**: 정산금 지급 처리 중 오류 발생 시 전체 롤백 처리 여부.

## 5. Playwright fixtures

사용자 시나리오 기반의 E2E 테스트를 위해 Playwright fixtures를 정의한다. 페르소나별 인증 상태를 미리 정의하여 로그인 과정을 생략하고 핵심 비즈니스 로직(North Star Metric 관련)을 빠르게 검증한다.

### 5.1 정의된 Fixtures
- `managerPage`: 이정훈(스케줄링 매니저) 권한으로 인증된 브라우저 컨텍스트. 스케줄 확정 및 자격 관리 페이지 접근 권한 포함.
- `crewPage`: 박소희(객실 승무원) 권한으로 인증된 브라우저 컨텍스트. 개인 스케줄 조회 및 정산서 다운로드 권한 포함.
- `adminPage`: SA(시스템 관리자) 권한으로 인증된 브라우저 컨텍스트. RBAC 설정 및 시스템 로그 접근 권한 포함.

### 5.2 테스트 시나리오 예시
- **스케줄 확정 흐름**: `managerPage` $\rightarrow$ 스케줄 배치 $\rightarrow$ 충돌 확인 $\rightarrow$ 확정 버튼 클릭 $\rightarrow$ `crewPage`에서 확정 상태 확인.
- **정산서 생성 흐름**: `managerPage` $\rightarrow$ 월말 정산 마감 $\rightarrow$ Puppeteer PDF 생성 요청 $\rightarrow$ `crewPage`에서 T02 템플릿 다운로드 및 내용 검증.
